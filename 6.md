# Kubernetes Workloads

A **workload** is an application running on Kubernetes. Workloads run inside **Pods**, and Kubernetes provides higher-level workload resources that create and manage Pods for you, so you rarely create Pods directly.

## Workload Types at a Glance

| Workload | Purpose | Runs | Pod identity | Typical use |
|---|---|---|---|---|
| Pod | Smallest deployable unit | Until deleted/fails | Ephemeral | Testing, debugging |
| ReplicaSet | Keep N identical Pods running | Continuously | Ephemeral | Used by Deployment |
| Deployment | Stateless apps with rolling updates | Continuously | Ephemeral | Web apps, APIs |
| StatefulSet | Stateful apps | Continuously | Stable name + storage | Databases, Kafka |
| DaemonSet | One Pod per node | Continuously | Per node | Log/monitoring agents |
| Job | Run to completion | Until success | Ephemeral | Batch, migrations |
| CronJob | Scheduled Jobs | On schedule | Ephemeral | Backups, reports |

---

## 1. Pod

The smallest deployable unit in Kubernetes. A Pod wraps one or more containers that share:

- Network namespace (same IP, localhost communication)
- Storage volumes
- Lifecycle

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: nginx-pod
spec:
  containers:
    - name: nginx
      image: nginx:1.27
      ports:
        - containerPort: 80
```

**Note:** A bare Pod is not rescheduled if its node fails. Use a controller (Deployment, etc.) for anything real.

---

## 2. ReplicaSet

Ensures a specified number of identical Pod replicas are running at any time. If a Pod dies, the ReplicaSet creates a new one.

```yaml
apiVersion: apps/v1
kind: ReplicaSet
metadata:
  name: nginx-rs
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
        - name: nginx
          image: nginx:1.27
```

**Note:** You normally don't create ReplicaSets directly. A Deployment manages them for you.

---

## 3. Deployment

The most common workload. Manages ReplicaSets and gives you declarative updates for **stateless** applications.

Features:

- Rolling updates and rollbacks
- Scaling (manual or via HPA)
- Self-healing through ReplicaSets

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-deploy
spec:
  replicas: 3
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxUnavailable: 1
      maxSurge: 1
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
        - name: nginx
          image: nginx:1.27
```

Useful commands:

```bash
kubectl rollout status deployment/nginx-deploy
kubectl set image deployment/nginx-deploy nginx=nginx:1.28
kubectl rollout undo deployment/nginx-deploy
kubectl scale deployment/nginx-deploy --replicas=5
```

**Use for:** web servers, REST APIs, microservices.

## 4. StatefulSet

Manages **stateful** applications. Unlike a Deployment, each Pod gets:

- A **stable, unique name** (`db-0`, `db-1`, `db-2`)
- **Stable network identity** via a headless Service
- **Its own persistent storage** (via `volumeClaimTemplates`) that follows the Pod across rescheduling
- **Ordered** creation, scaling, and deletion

```yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: mysql
spec:
  serviceName: mysql-headless
  replicas: 3
  selector:
    matchLabels:
      app: mysql
  template:
    metadata:
      labels:
        app: mysql
    spec:
      containers:
        - name: mysql
          image: mysql:8
          volumeMounts:
            - name: data
              mountPath: /var/lib/mysql
  volumeClaimTemplates:
    - metadata:
        name: data
      spec:
        accessModes: ["ReadWriteOnce"]
        resources:
          requests:
            storage: 10Gi
```

**Use for:** MySQL, PostgreSQL, MongoDB, Kafka, ZooKeeper, Elasticsearch.

---

## 5. DaemonSet

Ensures **one Pod runs on every node** (or on a selected subset of nodes). When a node is added, the Pod is added automatically; when a node is removed, the Pod is garbage collected.

```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: log-agent
spec:
  selector:
    matchLabels:
      app: log-agent
  template:
    metadata:
      labels:
        app: log-agent
    spec:
      containers:
        - name: agent
          image: fluent/fluentd:v1.17
```

**Use for:** log collectors (Fluentd, Filebeat), monitoring agents (Node Exporter), network plugins (kube-proxy, CNI), storage daemons.

---

## 6. Job

Runs one or more Pods **until a specified number complete successfully**. Failed Pods are retried according to `backoffLimit`.

```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: db-migrate
spec:
  completions: 1
  parallelism: 1
  backoffLimit: 4
  template:
    spec:
      restartPolicy: Never
      containers:
        - name: migrate
          image: busybox:1.36
          command: ["sh", "-c", "echo running migration && sleep 5"]
```

Key fields:

| Field | Meaning |
|---|---|
| `completions` | Number of successful Pod completions required |
| `parallelism` | Pods that can run at the same time |
| `backoffLimit` | Retries before the Job is marked failed |
| `ttlSecondsAfterFinished` | Auto-clean the Job after it finishes |

**Note:** `restartPolicy` must be `Never` or `OnFailure` for Jobs.

**Use for:** database migrations, batch processing, one-time tasks.

---

## 7. CronJob

Creates **Jobs on a repeating schedule**, using standard cron syntax.

```yaml
apiVersion: batch/v1
kind: CronJob
metadata:
  name: nightly-backup
spec:
  schedule: "0 2 * * *"
  concurrencyPolicy: Forbid
  successfulJobsHistoryLimit: 3
  failedJobsHistoryLimit: 1
  jobTemplate:
    spec:
      template:
        spec:
          restartPolicy: OnFailure
          containers:
            - name: backup
              image: busybox:1.36
              command: ["sh", "-c", "echo backing up"]
```

`concurrencyPolicy` options: `Allow` (default), `Forbid`, `Replace`.

**Use for:** scheduled backups, report generation, cleanup tasks.

---

## Choosing the Right Workload

| Need | Use |
|---|---|
| Stateless app with updates and scaling | Deployment |
| App needing stable identity and storage | StatefulSet |
| Agent on every node | DaemonSet |
| Run a task once to completion | Job |
| Run a task on a schedule | CronJob |
| Quick test or debug container | Pod |

## Useful Commands

```bash
kubectl get pods,rs,deploy,sts,ds,jobs,cronjobs
kubectl describe deployment <name>
kubectl get pods -o wide
kubectl delete -f <file>.yaml
```
