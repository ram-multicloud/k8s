# Kubernetes Cluster Installation using kubeadm (Ubuntu)

Install a multi-node Kubernetes cluster (1 master / control plane + worker nodes) on **Ubuntu 22.04 / 24.04** using `kubeadm`, `containerd` and Flannel.

---

## 1. Architecture

| Component | Runs on | Role |
|---|---|---|
| `kube-apiserver`, `etcd`, `kube-scheduler`, `kube-controller-manager` | Master | Control plane |
| `kubelet` | All nodes | Node agent; runs pods |
| `kube-proxy` | All nodes | Service networking |
| `containerd` | All nodes | Container runtime (CRI) |
| Flannel | All nodes | Pod network (CNI) |
| `kubeadm` | All nodes | Bootstraps the cluster (`init`, `join`) |
| `kubectl` | Master | CLI for the cluster |

## 2. Values used

| Setting | Value |
|---|---|
| Kubernetes version | `v1.34` |
| Container runtime | `containerd` with `SystemdCgroup = true` |
| Master hostname | `controlplane` |
| Pod network CIDR | `10.244.0.0/16` |
| CNI plugin | Flannel |

## 3. Prerequisites

| Requirement | Value |
|---|---|
| OS | Ubuntu 22.04 / 24.04 |
| CPU / RAM / Disk | 2 vCPU, 2 GB RAM (4 GB recommended), 20 GB disk per node |
| Network | All nodes can reach each other on private IPs |
| Unique per node | Hostname, MAC address, `product_uuid` |
| Access | Root / sudo and internet access |
| Pod CIDR | `10.244.0.0/16` must not overlap with the VPC / VNet range |

### Ports to open (Security Group / NSG)

**Master**

| Port | Purpose |
|---|---|
| 6443 | Kubernetes API server |
| 2379-2380 | etcd |
| 10250 | Kubelet API |
| 10257 | kube-controller-manager |
| 10259 | kube-scheduler |

**Workers**

| Port | Purpose |
|---|---|
| 10250 | Kubelet API |
| 10256 | kube-proxy |
| 30000-32767 | NodePort Services |

**Flannel (all nodes):** UDP 8472 (VXLAN) between nodes.

## 4. Installation flow

| Step | Where | Action |
|---|---|---|
| 1 | Master | Run the master script (Section 5) |
| 2 | Master | Copy the printed `kubeadm join` command |
| 3 | Each worker | Run the worker script (Section 6), then the join command |
| 4 | Master | Verify (Section 7) |

---

## 5. Master node installation

### Steps

1. Create the script:

   ```bash
   vi install-k8s-master.sh
   ```

2. Paste the script below and save.

3. Run it:

   ```bash
   sudo bash install-k8s-master.sh
   ```

4. Copy the `kubeadm join ...` command printed at the end.

### What the script does

| Step | Action |
|---|---|
| 1 | Sets hostname to `controlplane`, adds `/etc/hosts` entry |
| 2 | Disables swap (runtime and `/etc/fstab`) |
| 3 | Loads `overlay` and `br_netfilter` kernel modules |
| 4 | Sets sysctl: bridge-nf-call-iptables, bridge-nf-call-ip6tables, ip_forward |
| 5 | Installs containerd with the systemd cgroup driver |
| 6 | Adds the Kubernetes apt repo; installs and holds kubelet, kubeadm, kubectl |
| 7 | Runs `kubeadm init` with the Pod CIDR and API server IP |
| 8 | Configures kubeconfig, applies Flannel, prints the join command |

### Master script

```bash
#!/bin/bash
# Kubernetes control plane (master) installation using kubeadm on Ubuntu 22.04 / 24.04
# Usage: sudo bash install-k8s-master.sh

set -euo pipefail

if [ "$(id -u)" -ne 0 ]; then
  echo "Run as root: sudo bash $0"
  exit 1
fi

echo ">>> [1/8] Setting hostname to controlplane"
hostnamectl set-hostname controlplane
grep -q "controlplane" /etc/hosts || echo "$(hostname -I | awk '{print $1}') controlplane" >> /etc/hosts

echo ">>> [2/8] Disabling swap"
swapoff -a
sed -i '/ swap / s/^/#/' /etc/fstab

echo ">>> [3/8] Loading kernel modules"
cat <<EOF > /etc/modules-load.d/k8s.conf
overlay
br_netfilter
EOF
modprobe overlay
modprobe br_netfilter

echo ">>> [4/8] Setting sysctl parameters"
cat <<EOF > /etc/sysctl.d/k8s.conf
net.bridge.bridge-nf-call-iptables  = 1
net.bridge.bridge-nf-call-ip6tables = 1
net.ipv4.ip_forward                 = 1
EOF
sysctl --system > /dev/null

echo ">>> [5/8] Installing containerd"
apt-get update -y
apt-get install -y containerd apt-transport-https ca-certificates curl gpg
mkdir -p /etc/containerd
containerd config default > /etc/containerd/config.toml
sed -i 's/SystemdCgroup = false/SystemdCgroup = true/' /etc/containerd/config.toml
systemctl restart containerd
systemctl enable containerd

echo ">>> [6/8] Installing kubeadm, kubelet, kubectl (v1.34)"
mkdir -p -m 755 /etc/apt/keyrings
curl -fsSL "https://pkgs.k8s.io/core:/stable:/v1.34/deb/Release.key" \
  | gpg --dearmor --yes -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg
echo "deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] https://pkgs.k8s.io/core:/stable:/v1.34/deb/ /" \
  > /etc/apt/sources.list.d/kubernetes.list
apt-get update -y
apt-get install -y kubelet kubeadm kubectl
apt-mark hold kubelet kubeadm kubectl
systemctl enable --now kubelet

echo ">>> [7/8] Initializing control plane"
kubeadm init \
  --pod-network-cidr=10.244.0.0/16 \
  --apiserver-advertise-address="$(hostname -I | awk '{print $1}')"

echo ">>> [8/8] Configuring kubectl and installing Flannel CNI"
TARGET_USER="${SUDO_USER:-root}"
TARGET_HOME="$(getent passwd "${TARGET_USER}" | cut -d: -f6)"
mkdir -p "${TARGET_HOME}/.kube"
cp -f /etc/kubernetes/admin.conf "${TARGET_HOME}/.kube/config"
chown -R "${TARGET_USER}:${TARGET_USER}" "${TARGET_HOME}/.kube"

export KUBECONFIG=/etc/kubernetes/admin.conf
kubectl apply -f https://github.com/flannel-io/flannel/releases/latest/download/kube-flannel.yml

echo
echo "=============================================================="
echo " Control plane is ready. Run this on each WORKER node (as root):"
echo "=============================================================="
kubeadm token create --print-join-command
echo
echo "Verify with: kubectl get nodes"
```

## 6. Worker node installation

### Steps

1. On each worker, create the script:

   ```bash
   vi install-k8s-worker.sh
   ```

2. Paste the script below and save.

3. Run it (use a unique name for each worker, e.g. `worker1`, `worker2`):

   ```bash
   sudo bash install-k8s-worker.sh worker1
   ```

4. Join the cluster using the command copied from the master:

   ```bash
   sudo kubeadm join <MASTER_IP>:6443 --token <token> \
     --discovery-token-ca-cert-hash sha256:<hash>
   ```

   If the token expired (valid 24 hours), generate a new one on the master:

   ```bash
   kubeadm token create --print-join-command
   ```

### Worker script

The worker needs the same prerequisites as the master (swap, kernel modules, sysctl, containerd, kubeadm, kubelet), but **no** `kubeadm init`.

```bash
#!/bin/bash
# Kubernetes worker node preparation using kubeadm on Ubuntu 22.04 / 24.04
# Usage: sudo bash install-k8s-worker.sh <worker-hostname>

set -euo pipefail

if [ "$(id -u)" -ne 0 ]; then
  echo "Run as root: sudo bash $0 <worker-hostname>"
  exit 1
fi

if [ $# -ne 1 ]; then
  echo "Usage: sudo bash $0 <worker-hostname>"
  exit 1
fi

echo ">>> [1/6] Setting hostname to $1"
hostnamectl set-hostname "$1"
grep -q "$1" /etc/hosts || echo "$(hostname -I | awk '{print $1}') $1" >> /etc/hosts

echo ">>> [2/6] Disabling swap"
swapoff -a
sed -i '/ swap / s/^/#/' /etc/fstab

echo ">>> [3/6] Loading kernel modules and sysctl parameters"
cat <<EOF > /etc/modules-load.d/k8s.conf
overlay
br_netfilter
EOF
modprobe overlay
modprobe br_netfilter

cat <<EOF > /etc/sysctl.d/k8s.conf
net.bridge.bridge-nf-call-iptables  = 1
net.bridge.bridge-nf-call-ip6tables = 1
net.ipv4.ip_forward                 = 1
EOF
sysctl --system > /dev/null

echo ">>> [4/6] Installing containerd"
apt-get update -y
apt-get install -y containerd apt-transport-https ca-certificates curl gpg
mkdir -p /etc/containerd
containerd config default > /etc/containerd/config.toml
sed -i 's/SystemdCgroup = false/SystemdCgroup = true/' /etc/containerd/config.toml
systemctl restart containerd
systemctl enable containerd

echo ">>> [5/6] Installing kubeadm, kubelet, kubectl (v1.34)"
mkdir -p -m 755 /etc/apt/keyrings
curl -fsSL "https://pkgs.k8s.io/core:/stable:/v1.34/deb/Release.key" \
  | gpg --dearmor --yes -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg
echo "deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] https://pkgs.k8s.io/core:/stable:/v1.34/deb/ /" \
  > /etc/apt/sources.list.d/kubernetes.list
apt-get update -y
apt-get install -y kubelet kubeadm kubectl
apt-mark hold kubelet kubeadm kubectl
systemctl enable --now kubelet

echo ">>> [6/6] Worker node is ready"
echo "Now run the 'kubeadm join ...' command copied from the master (with sudo)."
```

## 7. Verify the cluster (on master)

```bash
kubectl get nodes -o wide
kubectl get pods -A
kubectl cluster-info
```

Expected:

```
NAME           STATUS   ROLES           AGE   VERSION
controlplane   Ready    control-plane   10m   v1.34.x
worker1        Ready    <none>          3m    v1.34.x
worker2        Ready    <none>          3m    v1.34.x
```

Optionally label the workers:

```bash
kubectl label node worker1 node-role.kubernetes.io/worker=
kubectl label node worker2 node-role.kubernetes.io/worker=
```

### Smoke test

```bash
kubectl create deployment nginx --image=nginx --replicas=2
kubectl expose deployment nginx --type=NodePort --port=80
kubectl get pods -o wide
kubectl get svc nginx
```

Open `http://<any-node-ip>:<nodeport>` in a browser, then clean up:

```bash
kubectl delete svc nginx
kubectl delete deployment nginx
```

## 8. Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| `kubeadm init` fails on swap | Swap still on | `sudo swapoff -a`, re-run |
| Node stays `NotReady` | CNI not ready | `kubectl get pods -n kube-flannel` |
| CoreDNS `Pending` | CNI not installed | Re-apply the Flannel manifest |
| Pods crash-loop | Cgroup driver mismatch | Confirm `SystemdCgroup = true`; restart containerd and kubelet |
| `join` times out | Port 6443 blocked | Check Security Group / NSG; `nc -vz <master-ip> 6443` |
| `join` token invalid | Token expired | `kubeadm token create --print-join-command` |
| `localhost:8080 refused` | kubeconfig missing | Copy `/etc/kubernetes/admin.conf` to `~/.kube/config` |
| Pod CIDR conflict | Overlaps VPC range | `kubeadm reset` and re-init with a different CIDR |

Debug commands:

```bash
journalctl -u kubelet -f
journalctl -u containerd -f
sudo crictl ps -a
kubectl describe node <node>
```

## 9. Reset a node (start over)

```bash
sudo kubeadm reset -f
sudo rm -rf /etc/cni/net.d $HOME/.kube/config
sudo systemctl restart containerd
```

To remove a worker properly, run on the master first:

```bash
kubectl drain <node> --ignore-daemonsets --delete-emptydir-data
kubectl delete node <node>
```
